# ورک‌اسپیس (اسم موقت)

ورک‌اسپیس فارسی برای تیم‌ها، با سه تب: تیم و تقویم، خوشه‌ها (کانبان) و اندوخته‌ها (مستندات). سند محصول در پوشه مشترک پروژه است (`spec/workspace-spec.md`).

**وضعیت:** فاز ۱ (بخش اول). حساب‌ها و پروفایل، ورک‌اسپیس‌ها، اعضا و سطح دسترسی، نقش‌های تیم، دعوت با نام کاربری و لینک، و اعلان‌ها آماده‌اند. تب‌های خوشه‌ها و اندوخته‌ها هنوز خالی‌اند.

## چه چیزی کجاست

| مسیر | چیست |
| --- | --- |
| `src/index.js` | ورودی سرور: هدر امنیتی، مسیرها، خطاها |
| `src/lib/` | ابزارهای مشترک سرور: پاسخ و خطا (`http.js`)، رمزنگاری (`crypto.js`)، مسیریاب (`router.js`) |
| `src/accounts/` | **حساب‌ها:** تنها جایی که جدول‌های `users`، `sessions`، `login_attempts` و `telegram_links` خوانده و نوشته می‌شوند (`store.js`)، ورود با تلگرام (`telegram.js`)، و API حساب (`routes.js`) |
| `src/workspaces/` | **ورک‌اسپیس‌ها:** سطح دسترسی (`access.js`)، اعضا، نقش‌های تیم، دعوت و لینک‌ها (`store.js`)، API (`routes.js`) |
| `src/notifications/` | اعلان‌های داخل اپ |
| `migrations/` | تغییرات دیتابیس، شماره‌دار |
| `web/src/` | صفحه‌ها: ورودی (`main.js`)، آدرس‌ها (`router.js`)، تماس با سرور (`api.js`)، پرسیدن تغییرها (`poll.js`)، متن‌ها (`i18n.js`)، هر صفحه در `pages/`، ظاهر در `style.css` |
| `web/public/` | فایل‌هایی که همان‌طور منتشر می‌شوند: `index.html`، فونت‌ها |
| `scripts/build.mjs` | ساخت صفحه‌ها در `dist/` با esbuild |
| `tests/unit/` | تست‌های سریع بدون سرور (`node --test`) |
| `tests/e2e/` | تست‌های کامل روی ورکر محلی (Playwright) |

## قاعده‌ها

1. **حساب‌ها فقط در `src/accounts/`.** بقیه کد فقط شناسه کاربر (`users.id`) را نگه می‌دارد و هر چیز دیگر را از `accounts/store.js` می‌پرسد.
2. **هر تغییر دیتابیس یک فایل مهاجرت تازه.** فایل قدیمی را عوض نکنید؛ `migrations/000N_….sql` بعدی را بسازید.
3. **هیچ رمز یا توکنی در کد نیست.** همه در تنظیمات Cloudflare.
4. **درخواست کم.** صفحه‌های باز با `poll.js` تغییرها را می‌پرسند: هر ۵ ثانیه بعد از یک تغییر، کم‌کم تا هر ۱ دقیقه وقتی خبری نیست، و هیچ وقتی تب پنهان است. سقف پلن رایگان Workers صد هزار درخواست در روز است.
5. **این مخزن به سه‌موز و حفظ و نشر وابسته نیست.** کد مفید آن‌ها کپی و تمیز می‌شود، نه import.

## راه‌اندازی روی Cloudflare (یک بار)

1. **دیتابیس:** ساخته شده (`workspace`) و شناسه‌اش در `wrangler.jsonc` است.
2. **اتصال به گیت‌هاب:** **Workers & Pages ← Create ← Import a repository**، این مخزن را انتخاب کنید. Build command را `npm run build` و Deploy command را `npm run deploy` بگذارید (این دستور اول مهاجرت‌های دیتابیس را اجرا می‌کند، بعد منتشر می‌کند).
3. **ربات تلگرام:** یک ربات تازه از @BotFather بسازید. در صفحه ورکر، **Settings ← Variables and Secrets ← Add**، نوع **Secret**، اسم `TELEGRAM_BOT_TOKEN`. اسم ربات را هم در `wrangler.jsonc` جلوی `BOT_USERNAME` بگذارید. در BotFather، **Configure Mini App** را با آدرس سایت فعال کنید.
4. **ساخت حساب:** به‌طور پیش‌فرض بسته است؛ فقط حساب‌هایی که از قبل در دیتابیس هستند وارد می‌شوند، با رمز در سایت یا با تلگرامِ وصل‌شده در مینی‌اپ. تلگرامی که به هیچ حسابی وصل نیست راه داده نمی‌شود. برای باز کردن ثبت‌نام، متغیر `OPEN_SIGNUP` را `1` بگذارید.
4. **دامنه:** فعلاً `work.inbovo.com`. در صفحه ورکر **Settings ← Domains & Routes ← Add ← Custom domain** (DNS دامنه باید روی همین حساب Cloudflare باشد). دامنه اصلی بعداً کنار آن اضافه می‌شود.

## اجرا روی کامپیوتر خودتان

```
npm install
npm run dev
```

بعد `http://localhost:8787` را باز کنید. برای امتحان تلگرام یک فایل `.dev.vars` با `TELEGRAM_BOT_TOKEN=...` بسازید؛ این فایل هرگز داخل مخزن نمی‌رود.

## تست‌ها

```
npm test             # همه: بررسی نوع‌ها، تست‌های سریع، تست‌های کامل
npm run test:unit    # فقط تست‌های سریع
npm run test:e2e     # فقط تست‌های کامل (یک ورکر محلی با دیتابیس خالی بالا می‌آورد)
```
